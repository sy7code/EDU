# 성장 페이스 — 기능 설계

## 단원 테스트 + 교사 종합 보드 (2026-11-13)

### 의도
교사가 **학습 시간·기록 내용·단원 테스트 결과를 한 화면에서 종합해** 학생이 어느 수준인지, 어떻게 공부하고 있는지 파악한다.
학생은 단원을 마칠 때 짧은 테스트로 스스로 확인하고 바로 해설을 본다.

### 목표 / 비목표 / 반목표
- 목표: 단원 단위 학습 기록, 단원 종료 시 객관식·O/X 테스트, 교사가 승인한 문제만 출제, 교사용 학생 종합 보드
- 비목표: 성적 산출, 주관식 자동 채점, 학생별 맞춤 문제 즉석 생성, 실제 LLM 연동(이번엔 mock)
- 반목표(이렇게 되면 실패): 승인 안 된 AI 문제가 학생에게 나감 / 테스트 결과가 줄세우기·성적에 쓰이는 것처럼 보임 / 기록 공유 미동의 학생의 결과가 교사에게 보임

### 접근 방식
| 방식 | 장단점 | 결정 |
|---|---|---|
| **A. AI 초안 → 교사 승인** | 교사 부담 적음, 교사가 오류를 막음, 팀 원칙(근거 기반·교차 확인)과 일치 | **선택 (사용자)** |
| B. 교사 문제은행 직접 등록 | 정확하지만 교사 부담 큼 | 제외 |
| C. AI가 학생 기록으로 즉석 출제 | 맞춤형이지만 정답 오류를 아무도 확인 안 함 | 제외 (원칙 위배) |

### 설계 (아래는 별도 표시 없으면 Claude 제안)
**데이터**
- `Unit { id, classId, subject, order, title, standard(성취기준 문장), material?(교사 자료 요약) }` — 해커톤은 시드(수학·영어·국어·과학 각 2~3단원)
- `QuizQuestion { id, unitId, type: "MCQ"|"OX", prompt, choices[], answerIndex, explanation, source: "AI"|"TEACHER", status: "DRAFT"|"APPROVED", evidence }`
  - `evidence`: AI 초안이 근거로 삼은 성취기준·자료 문장 (근거 없으면 초안을 만들지 않음)
- `QuizAttempt { id, sessionId, unitId, studentId, answers[], correct, total, createdAt }`
- `SessionGoal`에 `unitId?` 추가

**학생 흐름**
1. 학습 시작: 과목 선택 → 그 과목 단원 선택(선택 사항, "단원 없음" 가능) → 활동 체크
2. 학습 마치기(종료 인증 후): 단원이 있으면 "이 단원을 다 공부했어요" 체크 → **승인된 문제 최대 5개**(순서 섞음) 풀기
3. 제출 즉시 정답·해설 표시 → 돌아보기로 이어짐
4. "나중에 할게요" 가능 (부담 낮추기). 다음 학습에서 같은 단원으로 다시 응시 가능
5. 내 기록에 단원별 결과 표시

**교사 흐름**
- **단원 문제 관리** `/teacher/units`: 단원별 문제 목록, "AI 초안 만들기"(근거 문장 표시) → 수정·승인·삭제. 학생에겐 APPROVED만
- **학생 종합 보드**(학생 상세 상단): 단원별 행 — 학습 시간, 학습 횟수, 기록·질문 수, 최근 테스트 정답률, 학생이 매긴 이해도 → **"이해했다고 했지만 정답률 낮음"** 같은 차이를 신호로 표시
- 반 대시보드에 "최근 테스트" 열 추가

**규칙 (mock API + 테스트로 고정)**
- 학생은 APPROVED 문제만 받고, **응답 전에는 정답·해설을 받지 않음** (채점은 서버)
- 교사만 문제 생성·승인·수정, 자기 반 단원만
- 테스트 결과는 학습 기록 → **기록 공유 동의 없으면 교사에게 숨김** (기존 규칙과 동일)
- 응시는 세션당 단원 1회, ENDED 세션만
- 화면 문구: "테스트는 공부 확인용이에요. 성적에 들어가지 않아요."

### 빌더에게 맡기는 것
화면 배치, 단원 시드 내용, mock AI 초안 문구, 신호 기준값(예: 이해도 3인데 정답률 60% 미만).

> 이 버전은 태그 `v0.2-unit-quiz-teacher`로 보관. 아래 "주제별 성장" 설계로 대체한다.

## 주제별 성장 + 객관적 테스트 (2026-11-14, 위 단원 테스트를 대체)

### 의도 (사용자)
- 고교학점제라 과목이 많아 **과목·단원을 미리 정하지 않는다.** 학생은 공부하고 기록만 한다.
- **AI가 학습 기록으로** 무엇을 공부했는지(주제), 얼마나 진행됐는지 정리한다.
- **테스트는 학생 수준에 맞추지 않는다.** 주제마다 같은 기준(고정 난이도)으로 내서 학습 수준을 **객관적으로** 잰다.
- **AI 질문·답변(도우미)은 학생 수준에 맞춘다.**
- 문제는 교사가 만들지 않고 **AI가 생성**한다.
- 진행 기준은 **주제별 성장**(사용자 선택 A): 주제마다 학습 횟수·시간·테스트 정답률 변화.

### 목표 / 비목표 / 반목표
- 목표: 기록 기반 주제 추출, 주제별 고정 난이도 테스트, 주제별 성장 보드(학생·교사), 수준 맞춤 AI 도우미
- 비목표: 교육과정 성취기준 진도율(B안), 성적 산출, 주관식 채점
- 반목표: AI가 기록에 없는 주제를 지어냄 / 틀린 문제가 점수에 그대로 반영됨 / 같은 주제인데 이름이 달라 성장이 끊김 / 테스트 난이도가 학생마다 달라 비교 불가

### 접근 방식
| 방식 | 장단점 | 결정 |
|---|---|---|
| **1. feat/unit-quiz 테스트 기반 재사용, 단원 → AI 주제** | 출제 스냅샷 채점·선택지 섞기·세션당 1회·정답 비공개·동의 연동 규칙을 그대로 씀 | **선택 (사용자)** |
| 2. master에서 새로 | 깔끔하지만 검증된 규칙을 다시 만들어야 함 | 제외 |
| 3. 백엔드 LLM 먼저 | 가장 실제적이지만 백엔드 작업 선행 필요 | 1번 후 함수만 교체 |

### 설계 (별도 표시 없으면 Claude 제안)

**학습 흐름 (학생)**
1. 시작: "오늘 할 것" 자유 입력(필수, 200자) + 활동 체크(선택). 과목·단원 선택 없음. → 백엔드 `sessions.goal` 텍스트 그대로
2. 학습 중: 지금과 같음. AI 도우미는 **이 학생의 최근 주제 정답률·이해도를 보고 설명 깊이를 조절**(백엔드 프롬프트)
3. 마칠 때(종료 인증 후):
   - AI가 이번 기록에서 **주제 1~3개 추출**, 각 주제에 근거 기록 표시. 기록이 부족하면 "주제를 찾지 못했어요" → 테스트 없이 돌아보기
   - 학생이 "다 공부한 주제"를 하나 고름(또는 "나중에 할게요")
   - 그 주제로 **고정 난이도 5문항**(객관식·O/X): 정답·해설은 제출 후에만
   - 문제가 이상하면 **"이 문제 이상해요" 신고** → 그 문항은 채점에서 제외(분모에서 빠짐), 교사에게 모임
4. 돌아보기 → 내 기록(주제별 성장)

**주제 이름 일관성**
- 반 단위 **주제 사전**: AI는 추출할 때 반의 기존 주제 목록을 먼저 보고 **같은 개념이면 기존 주제를 고르고**, 없을 때만 새로 만든다(이름은 "개념 단위" 짧게, 예: "이차함수 꼭짓점").
- 과목은 AI가 추정해 태그로만 붙인다(필터용, 필수 아님).

**고정 난이도 (객관성)**
- 모든 주제·학생 공통 기준: "그 주제의 핵심 개념을 이해했는지 확인하는 교과서 기본 수준", 5문항, 개념 확인 3 + 적용 2.
- 문항은 **주제와 개념 설명을 근거로** 만들고, 학생 기록에서 문제를 베끼지 않는다(학생 기록은 주제 판단 근거로만).
- 같은 주제는 반 안에서 **문항 풀을 재사용**(학생 간 비교 가능). 풀이 5문항보다 적을 때만 새로 생성해 풀에 추가.

**성장 보드**
- 학생 "내 성장": 주제별 카드 — 학습 횟수·시간, 테스트 정답률 추이(처음 → 최근), 스스로 이해도
- 교사 학생 상세 상단: 같은 표 + 차이 신호(이해도 3인데 60% 미만 / 40% 미만, 같은 세션 짝)
- 교사 **신고된 문제** 화면: 신고 사유·문항·근거, "문항 제외 유지 / 신고 기각"

**규칙 (기존 그대로 유지)**: 학생 응답 전 정답·해설 비공개, 출제 스냅샷 채점, 선택지 섞기, 세션당 1회, 기록 공유 동의 없으면 교사에게 결과 비공개(mock), "테스트는 공부 확인용이에요. 성적에 들어가지 않아요." 문구

**프론트·백엔드 역할**
- 프론트: mock(키워드 사전으로 주제 추출 + 주제별 문항 풀) + `supabaseApi`에서 새 엔드포인트 호출, 화면 전부
- 백엔드(팀원): 실제 LLM 주제 추출·문항 생성 함수, 테이블 — **명세 v0.5 + 마이그레이션 SQL 초안을 프론트가 작성해 전달**
  - `POST /sessions/:id/topics` (ENDED, 캐시) → `{ topics: [{ topicId, name, subject?, evidenceIds }] }`
  - `POST /sessions/:id/quiz` `{ topicId }` → 문항(정답 제외), 스냅샷 저장
  - `POST /sessions/:id/quiz/submit` `{ answers }` → 채점 결과
  - `POST /quiz/questions/:id/report` `{ reason }`
  - RPC `student_topic_growth(student_id)`, `class_reported_questions(class_id)`
  - 테이블: `topics`(반 주제 사전), `session_topics`, `topic_questions`(문항 풀), `quiz_serves`, `quiz_attempts`, `quiz_reports`
- 백엔드 반영 전에는 실제 모드에서 이 기능을 숨긴다(`FEATURES.quiz`).

### 빌더에게 맡기는 것
mock 키워드 사전·문항 풀 내용, 화면 배치, 신고 사유 선택지("정답이 틀림 / 문제가 이해 안 됨 / 공부한 내용과 무관").

## 교사 반 분석 + 학생 종합 프로필 (2026-11-14)

### 의도
교사가 "반 전체는 어떤가(평균·분포)"와 "이 학생은 어떻게 공부했나(AI에 몇 번, 어떤 식으로 물었나)"를 화면 몇 개를 오가지 않고 한눈에 파악한다. 지금은 학습을 하나씩 열어야만 알 수 있다.

### 목표 / 비목표 / 반목표
- 목표: 반 분포·평균, 반이 공부한 주제, 학생별 AI 질문 횟수·유형·원문, 학생 값과 반 평균 비교.
- 비목표: AI로 질문 분류(다음 단계), 학생 순위표, 다른 반 비교, 내보내기.
- 반목표(이러면 실패): 학생 점수화·순위 매기기처럼 보임("기록은 평가가 아니라 대화의 출발점" 원칙 위반), 기록 공유 미동의 학생의 질문·정답률이 드러남, 자동 분류를 사실처럼 표시.

### 접근 (사용자 선택)
- A안 채택: '반 분석' 화면을 따로 두고, 학생 상세 위에 종합 프로필. (B안 "지금 대시보드에 열·요약 카드만 추가"는 분포가 약하고 질문을 깊게 보기 어려워 제외)
- 질문 유형: 1번 규칙 분류(프론트) 채택, "자동 분류 · 참고용" 표시. (2번 AI 분류는 백엔드 작업·일정 위험, 3번 분류 없음은 "답만 묻는 학생"을 찾기 어려워 제외)

### 설계
1. **반 분석 화면** `/teacher/analytics` (메뉴 "반 분석")
   - 기간: 최근 7일 / 최근 4주 (기본 4주) — Claude 기본값: 데모 데이터가 적어서.
   - 카드 3개: 학습 시간, 테스트 정답률, AI 질문 수. 각각 평균·중앙값 + 5구간 분포 막대.
   - 반이 공부한 주제 TOP 5: 주제 이름, 공부한 학생 수, 평균 정답률.
   - AI 질문 유형 비율(반 전체): 개념 이해 / 풀이 확인 / 답 요청 / 기타.
   - 학생 목록: 학습 시간·정답률·AI 질문 수·주로 한 질문 유형, 행을 누르면 학생 상세로.
2. **학생 종합 프로필** (학생 상세 맨 위)
   - 학습 횟수·시간, 최근 정답률, AI 질문 수 — 각 숫자 옆에 반 평균(▲▼).
   - 질문 유형 비율 + 질문 원문 목록(최근 순, 유형 배지, 어느 학습인지).
   - 아래는 지금처럼 주제별 성장 + 학습 목록. 학습 목록 항목에 AI 질문 수 표시.
3. **질문 분류 규칙** (순수 함수, 테스트로 고정): 답 요청 > 풀이 확인 > 개념 이해 > 기타 순서로 첫 번째 맞는 것. 키워드 목록은 구현 때 정함.
4. **데이터**: 새 Api `getClassAnalytics(classId, from, to)` → 기간 내 반 학생 세션, 학생 쪽 AI 메시지, 테스트 응시, 세션 주제. 집계는 순수 함수(`lib/analytics.ts`)로 하고 테스트로 고정. 실제 모드는 `v_sessions`·`v_ai_messages`·`v_quiz_attempts`·`v_session_topics`를 `in(...)`으로 묶어 조회(백엔드 수정 없음, RLS 그대로).
5. **개인정보**: 기록 공유 미동의 학생은 서버가 기록·AI 대화를 0건으로 준다 → 질문·정답률 집계에서 빠지고, 화면에 "기록 비공개 n명 제외"로 표시. 학습 횟수·시간은 대시보드와 같게 포함.
6. **차트**: 새 라이브러리 없이 CSS 막대 — Claude 기본값: 의존성 추가 없이 충분.

### 완료 기준

## 과목 라벨 · 과목별 다시 볼 주제 · 교과 교사 열람 (2026-11-14)

상태: 승인 (2026-11-14)

### 의도 (사용자)
- 학습이 끝나면 부족한 부분을 `수학 - 이차함수의 기울기`처럼 **과목 - 개념**으로 보고 싶다.
- 자기주도학습마다 과목 라벨을 붙여 모았다가 **그 과목 선생님**에게 전한다.
- 담임이 모든 과목에 피드백할 수 없으니, **교과 교사가 자기 과목만** 열람·피드백한다.
- 실제 적용 가능성과 도움 여부를 따진 뒤 방향 확정: 교과 교사는 개별 알림 대신 **반·과목 주간 집계**가 기본, 개별 열람·피드백은 선택(교사 부담·오판 위험 때문).

### 목표 / 비목표 / 반목표
- 목표: 학생이 과목별 다시 볼 주제를 한눈에 봄. 교과 교사가 맡은 반·과목의 주간 집계를 봄. 교과 교사가 동의한 학생의 자기 과목 기록만 열람·피드백. 담임은 지금처럼 전체를 보고 교과 피드백도 봄.
- 비목표: 메일·푸시 알림, 성취기준 매핑, 학년 공통 주제 사전(1-B), 배정 관리 화면(학교 관리자용), 학교 정보 연동, 시간표.
- 반목표: AI 판단으로 열람 권한이 바뀜. 교과 교사가 다른 과목·다른 반·미동의 기록을 봄. "부족하다"고 단정해 학생을 낙인찍음. 교과 교사에게 할 일이 쌓여 알림을 꺼 버림.

### 접근 방식 (사용자 승인)
- 개념 이름: **1-A 반 주제 사전 유지**, 교과 교사는 반별로 봄. 버린 것: 1-B 학년+과목 공통 사전(이동 작업·프롬프트 변경 필요), 1-C 성취기준 매핑(데이터 확보·정확도 미확인).
- 열람 기준: **2-가 학생이 고른 과목 `goal.subject`**. 버린 것: 2-나 AI가 붙인 주제 과목(권한을 AI가 정하게 됨).

### 설계 (별도 표시 없으면 Claude 제안)
- **용어**: 담임 = 반 전체를 보는 교사(지금의 교사). 교과 교사 = 배정된 반·과목만 보는 교사. 배정 = (교사, 반, 과목, 학기). 과목 라벨 = 학습 시작 때 고른 `goal.subject`. 다시 볼 주제 = 주제별 성장 신호 `LOW_SCORE`·`OVERCONFIDENT`인 주제(근거 문항 3개 이상, 기존 규칙).
- **학생**
  - 학습 마치기의 테스트 결과 아래: "다시 볼 주제" 목록 `수학 - 이차함수 그래프` 형식(이번 학습 주제 중 신호 있는 것).
  - 학생 홈 '오늘 할 일' 옆 또는 내 기록: 과목별로 묶은 다시 볼 주제(최근 것 위, 과목당 최대 3개).
  - 동의 설정에 새 항목 "교과 선생님에게 공개"(`SUBJECT_SHARE`), 기록 없으면 미동의. 문구: "수학으로 시작한 학습은 수학 선생님도 볼 수 있어요. '나만 보기' 기록은 보이지 않아요."
- **교과 교사**
  - 사이드바 "내 과목": 배정마다 카드(반·과목), 이번 주 학습 수·학습한 학생 수·다시 볼 후보가 많은 주제 상위 3개.
  - 반·과목 화면: 주제별 표(학습 학생 수, 다시 볼 후보 수, 최근 정답률), 많이 틀린 문항 2개(해설 링크), 동의한 학생 목록 → 학생 상세(그 과목 학습만).
  - 집계는 `SUBJECT_SHARE` 동의 학생만, 해당 학생 2명 이하인 칸은 "적음".
  - 피드백: 그 과목 학습의 돌아보기에만 쓸 수 있음. 학생·담임에게 "수학 선생님"으로 표시.
  - 개별 열람은 기존 열람 기록에 과목을 붙여 남김.
- **담임**: 지금과 같음. 교과 교사 피드백이 학생 상세에 과목과 함께 보임. 담임이면서 교과 교사면 사이드바에 "우리 반"과 "내 과목"이 함께.
- **권한 규칙(서버 RLS가 기준, 프론트는 같은 표로 표시만)**: 교과 교사가 학생 기록을 볼 수 있는 조건 = 현재 학기 배정(교사, 학생의 반, 학습의 `goal.subject`) 있음 AND 학생 `SUBJECT_SHARE` 동의 AND 기록 공개 범위 `TEACHER`. "기타" 과목은 교과 교사 없음.
- **계산 단위(구현자 점검 반영)**: 다시 볼 신호·근거 문항 수·최근 정답률은 **(주제, 학습 과목 `goal.subject`)** 단위로 센다. 같은 주제를 국어 학습에서 다뤄도 수학 교사 화면과 학생의 "수학 - 주제"에는 수학 학습의 테스트만 들어간다(다른 과목 기록이 섞이지 않게).
- **공개 범위**: 담임 규칙을 그대로 따른다. 학습 횟수·시간은 세션 단위로 셈, 주제는 원래 `TEACHER` 기록에서만 추출(백엔드 요청서 v0.1 134행), 기록 내용은 `TEACHER`만 보임. `PRIVATE` 기록만 있는 학습은 학습 수에는 들고 주제·후보에는 없음.
- **동의 관계**: `SUBJECT_SHARE`는 `LEARNING_RECORD`가 있을 때만 켤 수 있다(교과 교사가 담임보다 더 보지 않게). `LEARNING_RECORD`를 끄면 교과 공개도 꺼진 것으로 본다.
- **교사 계정**: `role`은 `teacher` 그대로. 담임 여부 = `classId` 있음, 교과 = 현재 학기 배정 있음. 교과만 맡은 교사는 `classId`가 없고 로그인 후 "내 과목"으로 감. 배정은 별도 API `listMyAssignments()`로 받음.
- **현재 학기**: 서울 날짜로 계산. 3~8월 = `YYYY-1`, 9~12월 = `YYYY-2`, 1~2월 = `(YYYY-1)-2`. 함수 `currentTerm(now)`.
- **많이 틀린 문항**: 그 반·과목 이번 주 응시에서 정답률 낮은 문항 2개(문항 글 + 정답률, 응시 3명 이상인 문항만). 해설 링크·새 교사용 문항 화면은 넣지 않음.
- **"적음" 적용 범위**: 학생 수가 들어가는 칸(카드 요약의 학습 학생 수 포함, 주제별 후보 수)과 문항 정답률(응시 3명 미만)에 적용. 학습 학생이 2명 이하면 카드 전체를 "이번 주 기록 적음"으로. 지난주 비교는 넣지 않음.
- **데모 데이터**: mock 시드에 교과 교사 1명(수학, 반 c1·c2)과 담임 겸 국어 교사 배정 추가. 데모 로그인 버튼에 "수학 선생님" 추가.
