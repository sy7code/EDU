# 관점 점검 — 과목 라벨 · 과목별 다시 볼 주제 · 교과 교사 열람 (2026-11-14)

범위: 학습을 과목으로 라벨링하고, 학생에게 "과목 - 다시 볼 주제" 목록을 보여 주며, 담임 외 교과 교사가 자기 과목만 반별 집계로 보고 필요하면 개별 기록을 열람·피드백하는 기능.
사용자 결정: 반 주제 사전 유지·교과 교사는 반별로 봄(1-A), 열람 범위는 학생이 고른 과목 `goal.subject` 기준(2-가), 교과 교사는 집계 기본·개별 열람/피드백 선택.

## 먼저 정할 질문 (영향 큰 순서, 답이 없으면 추천 기본값으로 진행)
1. 교과 교사 공개를 담임 공개(`LEARNING_RECORD`)와 **별도 동의**로 받을까? → 추천: 별도(`SUBJECT_SHARE`), 기록 없으면 미동의. 담임만 허락하고 교과 교사는 거절할 수 있어야 함.
2. 집계에서 **2명 이하**인 주제는 숫자를 감출까? → 추천: 감춤("적음"), 이름 목록은 개별 열람에서만.
3. 한 교사가 **담임이면서 교과 교사**일 수 있게 할까? → 추천: 가능. 담임 반은 전체, 다른 반은 과목만.
4. 과목을 **"기타"**로 고른 학습은? → 추천: 담임만 봄(교과 교사 없음).
5. 교과 교사가 쓴 피드백을 **담임도** 볼까? → 추천: 봄, "수학 선생님"처럼 과목 표시.
6. 집계 기간은? → 추천: 이번 주(서울 월~일)만. 지난주 비교는 넣지 않음(범위 축소).
7. 교과 교사에게 **알림(메일·푸시)**을 보낼까? → 추천: 보내지 않음. 대시보드에 주간 집계만(알림 피로 방지).

## 확인 필요 (법·규제)
- 담임 외 교사에게 학습 기록을 공개할 때 별도 동의가 필요한지, 기존 동의로 충분한지: 개인정보보호법상 제공·이용 범위 해석 — 전문가나 공식 안내로 확인 필요.
- 만 14세 미만 학생의 새 동의 항목에 보호자 동의가 필요한지(기존 동의와 같은 취급인지) — 확인 필요.
- 교사 열람 기록의 보관 기간 — 학교 지침 확인 필요.

## 추가 점검 — QR 단일 인증 (2026-11-14, 브랜치 feat/qr-only)
- 위험: **휴대폰 없는 학생은 학습을 시작할 수 없다**(대체 수단 제거). 사용자가 수용했다. 형평성 문제가 제기되면 다시 논의(decisions 28번).
- 가정: 교실 단말기에 **USB·블루투스 QR 스캐너**(키보드 입력 방식)를 연결한다. 하드웨어 선정·구매는 미정. 스캐너가 없으면 토큰 글자를 직접 입력해야 해 불편하다.
- 실제 모드는 백엔드 QR 배포 전까지 개발용 '인증 건너뛰기'로만 동작(인증 없음). 배포 전 운영 노출 금지.
