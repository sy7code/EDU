# 기능 고도화 계획 (학생·교사 관점)

작성 2026-11-14. 기준: 지금 master(`dcf8d0e`)의 기능, 이번 세션에서 화면을 돌며 찾은 문제, 해커톤 심사 배점.
기능 구현이 아니라 "무엇을 왜 먼저 할지"를 정하는 문서다. 항목마다 근거가 있는 것만 적고, 추정은 표시한다.

## 0. 판단 기준

심사 배점(100): 현장 문제 이해 20 · 해결 효과 15 · 해결 방안 적절성 15 · 현장 적용 가능성 15 · 윤리성 10 · 독창성 10 · 구체화(시나리오·화면·프로토타입) 10 · 발표 5.
→ 기능 수보다 **"현장 문제 → 이 기능이 그 문제를 줄인다"가 데모에서 보이는 것**이 점수가 크다. 그래서 우선순위는
1) 데모 흐름에서 바로 보이고, 2) 프론트만으로 되고(백엔드는 DB 재설치 중단 상태), 3) 윤리 감점을 막는 것 순서로 정한다.

| 우선순위 | 뜻 |
|---|---|
| **P0** | 데모 전에 한다. 작고, 데모 시나리오에 직접 나온다 |
| **P1** | 시간이 남으면 한다. 효과는 크지만 범위가 크거나 백엔드가 필요 |
| **P2** | 발표에서 "다음 단계"로 말한다. 구현하지 않는다 |

규모: S(반나절 이하) · M(하루 안팎) · L(그 이상). BE = 백엔드 작업 필요.

## 1. 지금 되는 것 (요약)

- 학생: 동의 → 학습 시작(목표·활동) → 단말기 인증 → 기록 4종·AI 도우미 → 종료 인증 → AI 주제 추출 → 확인 테스트 5문항·신고 → 결과·해설 → 체크리스트 돌아보기 → 홈 요약·내 기록·내 성장, 피드백 읽음, 내 기록 열람 기록 보기.
- 교사: 반 대시보드(상태 카드·검색·10명씩) → 반 분석(분포·주제 TOP 5·질문 유형) → 학생 상세(요약/학습 기록/AI 질문 탭, 피드백 작성, 열람 기록 남김) → 신고된 문제 처리.

## 2. 사용자 흐름별 문제 진단

### 학생
| 장면 | 지금 | 문제(근거) |
|---|---|---|
| 다음에 뭘 공부할지 | 홈은 "학습 시작" 버튼과 지난 기록뿐 | 돌아보기의 "남은 질문", 테스트에서 틀린 문항이 **다음 학습으로 이어지지 않음**. 자기주도학습의 핵심 고리(계획→실행→점검→다음 계획)가 끊김 |
| 틀린 문제 | 결과 화면과 기록 상세(접힘)에만 있음 | 틀린 문항을 모아 볼 곳이 없음. 같은 주제 재응시는 문항이 바뀜(4-8) → 복습 경로가 없음 |
| 테스트 대기 | 첫 출제 12.9초(백엔드 측정 1회) | 스피너만 보이면 데모에서 "멈췄다"로 보일 위험 |
| 피드백 받은 뒤 | 읽음 처리까지 | 학생이 반응할 방법이 없음(이해했어요/질문 있어요). 교사-학생 대화가 한 방향 |
| 기록 부담 | 매번 타이핑 | "쓰기 싫은 학생" 원칙(교육 메모)에 비해 빠른 입력 수단이 종이 기록 버튼 하나뿐 |

### 교사
| 장면 | 지금 | 문제(근거) |
|---|---|---|
| 아침에 누구부터 | "이야기 나눠 볼 학생" 배지 | **왜** 그 학생인지(질문 3개 이상? 기록 없음?)는 배지 글자로만, 무엇을 말할지 제안 없음 |
| 피드백할 돌아보기 | 학생을 하나씩 열어야 앎 | 백엔드 대시보드가 `hasReflectionWithoutFeedback`을 주는데 프론트가 **버리고 있음**(`supabaseMappers.ts` RawDashboardRow에만 있고 DashboardRow엔 없음) |
| 피드백 후 | 보내고 끝 | 학생이 읽었는지 모름. `v_feedback.readAt`이 이미 있는데 교사 화면에 표시 안 함 |
| 수업 준비 | 반 분석은 주제·정답률까지 | **어느 문항을 많이 틀렸는지(오개념)** 를 볼 수 없음. 응시 items에 문항별 정오가 있는데 집계 안 함 → "현장 적용"에서 가장 설득력 있는 장면이 빠짐 |
| 학생 질문 | 학생 상세 AI 질문 탭 | 학생이 돌아보기에 남긴 "남은 질문"을 반 전체로 모아 볼 곳이 없음(대시보드엔 개수만) |
| 같은 오개념 여러 명 | 학생마다 피드백 | 한 번에 여러 학생에게 같은 피드백을 보낼 수 없음 |

### 공통·윤리
| 문제 | 근거 |
|---|---|
| 동의 기록이 없으면 "공유"로 간주 | 백엔드 노트(데모 호환). 발표 한계로 명시하기로 함 |
| 열람 기록은 학생 상세만 | 반 분석·대시보드 조회는 남지 않음(문구로 밝힘) |
| 데모 계정 공유 | 사용자와 백엔드 테스트가 같은 계정을 동시에 써서 회귀 3건 실패 |
| 만 14세 미만 보호자 동의 | 자기 신고값(실제 인증 아님) |

## 3. 개선 항목

### P0 — 데모 전 (프론트만)

| ID | 관점 | 제안 | 효과·심사 | 규모 |
|---|---|---|---|---|
| T1 | 교사 | **"왜 이 학생" 이유 + 대화 제안**: 배지 옆에 근거("남은 질문 4개", "7일 기록 없음", "이해했다는데 점수 낮음")와 한 줄 대화 제안 | 해결 효과·적용 가능성: 교사가 바로 행동 | S |
| T9 | 교사 | **피드백 기다리는 돌아보기**: `hasReflectionWithoutFeedback` 살려서 대시보드 상태 카드·필터·배지로 | 버려지던 데이터 활용, 피드백 누락 방지 | S |
| T5 | 교사 | **피드백 읽음 표시**: 학생 상세 피드백 목록에 "읽음 ○○:○○ / 아직 안 읽음" | 교사-학생 순환이 보임 | S |
| T3 | 교사 | **주제별 많이 틀린 문항**: 반 분석 주제 TOP 5에서 주제를 누르면 문항별 정답률(낮은 순) + 학생 수. 신고·제외 문항은 빼고 계산 | "수업에 반영" 장면. 현장 적용·해결 효과 | M |
| S1 | 학생 | **다음 학습 제안**: 홈에 "지난번 남은 질문"·"틀린 문항 주제"를 카드로, 누르면 학습 시작의 "오늘 할 것"에 채워짐 | 자기주도 고리 완성. 해결 효과 | M |
| S7 | 학생 | **테스트 생성 대기 화면**: 단계 문구("기록에서 주제 확인 → 문항 만드는 중 → 거의 다 됐어요")와 예상 시간 "10초쯤" | 데모 리스크 제거 | S |
| D1 | 공통 | **데모 시나리오·계정 정리**: 발표용 흐름 스크립트(`docs/02-scenarios.md`), 데모 시간대 백엔드 테스트 금지 합의, 가능하면 학생 데모 계정 2개 이상 | 구체화 점수, 공유 DB 간섭 방지 | S |

|---|---|---|---|---|

| T4 | 교사 | **남은 질문 모아보기**: 반 학생들이 돌아보기에 남긴 "남은 질문"을 한 화면에, 답한 것(피드백)/안 한 것 구분 | 질문 방치 방지 | M |

## 4. P0 진행 순서와 완료 기준

순서: **T9 → T1 → T5 → S7 → T3 → S1 → D1** (작고 확실한 것부터, 데모 핵심 장면인 T3·S1은 그 다음).

| ID | 완료 기준(실행으로 확인) |
|---|---|
| T9 | 매퍼 테스트: `hasReflectionWithoutFeedback`이 DashboardRow로 넘어옴. 실제 모드 대시보드에 "피드백 기다림 n명" 카드·필터 |
| T1 | 순수 함수 테스트: 학생 행 → 이유 목록·대화 제안(남은 질문, 기록 없음, 신호). 화면에 이유 표시 |
| T5 | 학생 상세 피드백에 읽음 시각/안 읽음 표시(실제 모드 시드 31건 중 13건 읽음과 일치) |
| S7 | mock 지연을 13초로 두고 단계 문구가 바뀌는 것 확인 |
| T3 | 순수 함수 테스트: 응시 items → 문항별 정답률(신고·제외 제외, 응시 0 처리). 실제 모드 주제 클릭 시 문항 목록 |
| S1 | 순수 함수 테스트: 최근 돌아보기 남은 질문 + 최근 틀린 주제 → 제안 최대 3개. 누르면 학습 시작 입력칸에 채워짐 |
| D1 | `docs/02-scenarios.md`에 학생·교사 데모 흐름(클릭 순서, 보여줄 숫자), 백엔드와 데모 시간 합의 |

## 5. 확인하지 못한 것 · 사용자 결정 필요

- **현장 근거**: "교사가 아침에 무엇을 먼저 보는지", "학생이 기록을 귀찮아하는지"는 이 문서의 추정이다. 현직 교사 1~2명에게 T1·T3·S1 화면을 보여 주고 반응을 받으면 "현장 문제 이해(20점)" 근거가 된다.
- T2(일괄 피드백)는 학생 개인 기록에 같은 문장이 들어가 개별 피드백처럼 보일 수 있다 → "반 전체 안내" 표시를 둘지 결정 필요.
- S3·E3은 백엔드 작업이 필요하다. 백엔드가 DB 재설치를 멈춘 상태라 스키마 추가는 미리 합의해야 한다.
