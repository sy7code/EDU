# 계획: Pace 성장 그래프 · 종이 기록 사진 OCR · 휴대폰으로 이어 올리기 (2026-11-14, 사용자 승인)

## 사용자 결정
- OCR: **서버에서 AI(비전)가 글자를 읽음**. 학생이 확인·수정한 뒤 '종이에 기록'으로 저장.
- 중복 로그인: **PC에서 학습 중에 같은 계정으로 휴대폰에도 로그인해 종이를 찍어 올림.**
- Pace 기준: **학생 자기 평소(지난 기록)와 비교**. 반 친구와 비교하지 않음.
- 보는 사람: **학생 홈 + 교사 학생 상세**(교사는 기록 공유 동의 학생만).

## 1. Pace 지수 (하루 100점)

참고 화면의 항목·배점(지속성 25 / 과정 기록 25 / 성찰 20 / 목표 달성 30)을 지금 있는 데이터로 계산한다. 새 입력칸은 만들지 않는다.

| 항목 | 배점 | 계산 (그날 학습 기준) | 비교 기준 |
|---|---|---|---|
| 학습 지속성 | 25 | 그날 학습 시간 ÷ **내 평소 하루 학습 시간** × 25, 최대 25 | 평소 = 최근 28일 중 학습한 날의 학습 시간 중앙값 (기록이 3일 미만이면 30분) |
| 학습 과정 기록 | 25 | 그날 의미 있는 기록 수 ÷ **내 평소 하루 기록 수** × 25, 최대 25 | 의미 있는 기록 = 10자 이상 메모·궁금한 점, 종이 기록(사진 OCR 포함). 평소 = 최근 28일 학습한 날 평균 (최소 2) |
| 자기 성찰 | 20 | 돌아보기 있음 6 + 체크 2개 이상 6 + 남은 질문 또는 메모 8 | 절대 기준 (돌아보기는 양이 아니라 했는지가 중요) |
| 목표 달성 | 30 | 돌아보기 "세운 목표를 끝까지 했다" 체크 15 + 확인 테스트 정답률 × 15 (테스트 안 봤으면 체크로만 30 환산) | 절대 기준 |

- 하루에 학습이 여러 번이면 합쳐서 계산. 학습 안 한 날은 그래프에 점을 찍지 않고 빈 칸.
- 그래프: 이번 주 월~금 꺾은선(참고 화면처럼), 요일 칩을 누르면 그날 항목별 막대. 오른쪽 위 "이번 주 상승세 / 비슷해요 / 지난주보다 낮아요" 칩(첫 학습일과 마지막 학습일 차이 ±5점 기준).
- 아래 한 줄 피드백은 **규칙 기반 문장**(AI 호출 없음). 예: "이번 주 Pace 지수는 월요일보다 16점 높아졌어요. 기록이 평소보다 많았던 날 점수가 높았어요."
- 안내 문구 고정: "Pace 지수는 내 평소 기록과 비교한 참고 점수예요. 성적에 들어가지 않아요."
- 교사 화면: 학생 상세 요약 탭 "한눈에 보기" 아래 같은 그래프. 기록 공유 미동의 학생은 그래프 대신 "기록 비공개".

**결정(사용자): 안 A** — 교사와 학생이 같은 점수를 보려면 계산에 쓰는 기록 범위가 같아야 한다.
- 안 A(권장): **교사 공개 기록 + 종이 기록만** 점수에 넣는다. '나만 보기' 메모는 점수에 안 들어감(학생 화면에 그렇게 안내). 비공개 메모의 개수도 교사에게 드러나지 않음.
- 안 B: 학생 화면은 '나만 보기'까지 넣고, 교사 화면은 공개 기록만 → 두 화면 점수가 다를 수 있음.

구현: 순수 함수 `lib/pace.ts`(TDD), API `getPaceInputs(studentId)`(학생 본인·교사 자기 반). 실제 모드는 기존 view(`v_sessions`, `v_entries`, `v_reflections`, `v_quiz_attempts`)로 읽어 프론트에서 계산 → **백엔드 변경 없음**. 그래프는 새 라이브러리 없이 SVG로.

## 2. 종이 기록 사진 OCR

- 학습 중 화면의 '종이에 기록' 탭에 "사진으로 올리기" 버튼(휴대폰은 카메라 바로 열림, `accept="image/*" capture="environment"`).
- 브라우저에서 긴 변 1600px·JPEG로 줄여서(약 0.5MB) 서버로 보냄 → 인식된 글자를 입력칸에 채움 → 학생이 고친 뒤 "기록하기". 사진은 저장하지 않음.
- AI 동의가 없으면 버튼 대신 "AI 사용에 동의해야 사진 글자 인식을 쓸 수 있어요" 안내(손으로 입력은 그대로 가능).
- 대기 문구: "사진에서 글자를 읽는 중이에요 · 보통 5초쯤".
- mock: 예시 글자를 돌려줌(오류 강제 키로 실패 화면 확인 가능).
- **백엔드 필요**: 아래 v0.8 요청 A.

## 3. 휴대폰으로 이어 올리기 (중복 로그인)

- 같은 계정으로 PC와 휴대폰에 동시에 로그인해도 서로 끊기지 않아야 한다. 프론트는 로그아웃을 `scope: "local"`로 바꿔 둬서 한쪽 로그아웃이 다른 쪽을 끊지 않음. 동시 로그인 자체를 막는 코드는 프론트에 없음 → **백엔드 설정 확인 필요**(v0.8 요청 B).
- PC 학습 중 화면의 '종이에 기록' 탭에 "휴대폰으로 올리기" QR: 이 학습 화면 주소(`/student/session/:id?kind=PAPER`)를 담음. 휴대폰에서 찍으면 (로그인 안 돼 있으면 로그인 후) 바로 그 학습의 종이 기록 탭이 열림. QR에는 학습 ID만 들어가고 비밀번호·토큰은 넣지 않음.
- 휴대폰에서 올린 기록은 PC 화면에 몇 초 안에 보이게(기록 목록 5초 새로고침, 실서비스는 Realtime).
- QR 생성은 새 의존성 없이 하려면 직접 구현이 필요 → **결정(사용자): 새 의존성 `qrcode`(MIT) 추가**(라이선스·보안 확인 후 버전 고정).

## 완료 기준
1. `npx vitest run`: `lib/pace.ts` 항목별 계산·평소 기준·빈 날·여러 번 학습한 날·미동의 처리, mock `getPaceInputs`·OCR(동의 없음, 오류) 테스트 통과.
2. `npx tsc -b --noEmit` 출력 없음, `npx vite build` 성공.
3. mock 화면: 학생 홈 Pace 카드(그래프·요일 칩·항목 막대·피드백), 교사 학생 상세 그래프, 사진 올리기 → 글자 확인 → 저장, QR 표시, 375px 넘침 없음.
4. 백엔드 요청서 v0.8 작성.

## 백엔드 요청 v0.8 (초안)
- A. `POST /sessions/:id/ocr` body `{ image: "data:image/jpeg;base64,..." }`(≤2MB) → `{ text }`. 학생 본인·ACTIVE 세션만, AI 동의 필요(`CONSENT_REQUIRED`), 호출 제한 포함, 이름·연락처 마스킹, **사진은 저장·로그하지 않음**, 실패 시 `AI_TIMEOUT`/`AI_BAD_OUTPUT`.
- B. 같은 학생 계정 동시 로그인(PC + 휴대폰) 허용 확인(Supabase Auth 단일 세션 제한을 켜지 않았는지), 휴대폰 브라우저에서 함수 CORS 확인.
- C. (선택) 기록 목록 Realtime 구독 허용.
